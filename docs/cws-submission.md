# Chrome Web Store submission dossier — Crest Take

Everything the Chrome Web Store asks for, with the value to paste, and the
policy each value answers. Policy sources are linked at the bottom; quotes are
from the pages as of 2026-10-27.

## 1. Preconditions (on your Google account, not in the repo)

| requirement | detail |
|---|---|
| Developer account | <https://chrome.google.com/webstore/devconsole> → first visit asks you to accept the developer agreement and pay the **one-time $5** registration fee. |
| 2-Step Verification | *"2-Step Verification is required for all developer accounts prior to publishing an extension or updating an existing extension."* Turn it on for the Google account behind the publisher. |
| Item limit | A new publisher is capped at **2 published extensions**. Crest Take is 1 of 2. |
| Review time | *"For most extensions, review is completed within a few days, but it can take up to a few weeks."* First submission from a new publisher is one of the signals that makes a reviewer look more closely. |
| Contact inbox | Use an address you actually read — takedown and rejection notices go there, and *"failing to respond could result in the removal of your item."* |

## 2. The package

The store takes a ZIP whose **manifest is at the root**, not inside a folder.

```
manifest.json
x.js
icon128.png
```

Everything else in the repository (`test/`, `docs/`, `tools/`, `README.md`,
`LICENSE`, `PRIVACY.md`) is source material, not part of the package. Build the
ZIP with:

```powershell
Compress-Archive -Path manifest.json,x.js,icon128.png -DestinationPath crest-take-1.0.0.zip
```

The icon must be **128x128 PNG** in the package: *"You must provide a
128x128-pixel extension icon image in the ZIP file of your extension."*
`icon128.png` is generated by `node tools/make-icon.js`.

## 3. Store Listing tab

### Summary (≤ 132 characters)

```
Save the highest-bitrate MP4 from a video post with one click. Runs on x.com, keeps nothing, uploads nothing.
```

(109 characters — the same string as the manifest `description`.)

### Description

```
Crest Take adds one button to every video post on x.com. Click it and the
post's highest-bitrate MP4 is saved to your Downloads folder.

How it works
• The button appears in the action bar of any post that carries a video.
• One click resolves that post through x.com's own GraphQL operation, picks
  the highest-bitrate MP4 among the variants on offer, and hands the URL to
  Chrome's download manager.
• The button reports pending, then saved or failed, so you always know where
  the file is.

What it does not do
• No panel, no queue, no options page, no account, no telemetry.
• No persistent state — nothing is stored between clicks, because there is no
  storage permission to store it with.
• No upload. The file goes straight from x.com to your Downloads folder.

Permissions
• downloads — to hand the resolved URL to Chrome's download manager. That is
  the only permission, and there are no host permissions at all.

Privacy
The extension reads the post you clicked and the ct0 cookie of your x.com
session, and sends both back to x.com and nowhere else. It has no server and
no analytics. Full policy: https://github.com/tulior/crest-take/blob/main/PRIVACY.md

This is an unofficial client, not affiliated with X Corp. Please respect the
rights of content creators when you save media.
```

## 4. Privacy tab

### Single purpose

```
Save the highest-bitrate MP4 of a video post on x.com, on demand, with one click.
```

### Permissions justification

```
downloads — the extension resolves the media URL of the post the user clicked
and hands it to Chrome's download manager. It does not read the downloaded
file, and no other permission is required: there is no storage permission
because nothing is persisted, and no host permission because the extension
neither fetches media nor runs a background agent.
```

### Remote code

Select **"No, I am not using remote code."** — with this in the notes field, so
the reviewer sees it before they go looking:

```
The extension reads two strings from x.com's public JavaScript bundle
(abs.twimg.com): the id of the GraphQL operation it must call, and the public
app-level bearer token that x.com's own web client sends. The bundle is
fetched as text and two strings are matched out of it with a regular
expression. No code from that file is evaluated, imported, or executed, and
the extension's entire behaviour lives in the submitted package. The bearer is
a public constant published in that bundle, not a user credential.
```

This is the one place where a reviewer may probe, so the explanation belongs in
the open rather than in a comment. The policy allows exactly this shape:
*"The extension may reference and load data and other information sources that
are external to the extension"* and lists *"Fetching remote resources that are
not used to evaluate logic"* as permitted.

### Data usage disclosure

Check these, and only these:

- **Website content** — the clicked post's id, author handle and text, read
  from the page, used to request that post's media and to name the saved file.
- **Authentication information** — the `ct0` cookie of the user's own x.com
  session, sent back to x.com only, to authenticate that one request.

Do **not** check browsing activity, personal communications, PII, or health
information: the extension never reads them. Note the policy's consistency
rule — *"If the information listed in your privacy fields contradicts the
information provided in your privacy policy, or the behavior of your extension,
your extensions may be removed from the Store."* `PRIVACY.md` says exactly
this and nothing more.

Then tick the certification checkboxes (allowed use, allowed transfer, no
advertising use, no human reading of data).

### Privacy policy URL

```
https://github.com/tulior/crest-take/blob/main/PRIVACY.md
```

Also add it on the **account page** — the policy requires the link in both
places: *"You must make the policy accessible by providing a link in the
designated Chrome Web Store Developer Dashboard field."* The file already
carries the Limited Use affirmative statement, which the policy requires to be
*"on a website belonging to your extension"* — the repository is that website.

## 6. Test instructions

Worth filling in: the extension only does anything on a logged-in `x.com`
account, and a reviewer without one cannot exercise it.

```
1. Sign in to x.com in the test profile (a reviewer account with access to at
   least one public video post is enough; the extension reads only what that
   session can already see).
2. Open any post that carries a video. A blue ⬇ button appears in the post's
   action bar.
3. Click it. The button shows … while the post is resolved, then ✓ when
   Chrome's download manager has saved the file to Downloads/x-videos/.
4. If the post cannot be resolved, the button shows ✕ and stays usable.

No account, no configuration, no API key. The extension needs only the
permission Chrome asks for on install (downloads).
```

## 7. Posture notes — read before you submit

- **Video downloaders are allowed but never featured.** *"Certain products that
  don't meet these standards, but which don't explicitly violate Chrome Web
  Store policies — such as VPN extensions and video downloaders — may be
  restricted from feature in the store, but will still be available to users."*
  Do not expect a marquee slot or a collection placement.
- **The copyright line is the real risk.** *"Do not encourage, facilitate, or
  enable the unauthorized access, download, or streaming of copyrighted content
  or media."* The mitigations are already in the design: the extension saves
  only what the user's own session can already play, it bypasses no paywall or
  login, it has no bulk or batch mode, it hosts nothing, and it has no ads or
  affiliate links. The listing says so plainly. Keep the language factual —
  no "download anything", no "without limits".
- **First submission gets a closer look.** *"new developers"*, *"new
  extensions"* and *"dangerous permission requests"* all lengthen review. One
  permission, no host permissions, readable source: that is the shortest
  possible review.
- **Two-step verification is not optional** on the Google account, and the
  $5 fee is a one-off, not per extension.
